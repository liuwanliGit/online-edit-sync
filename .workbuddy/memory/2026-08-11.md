# 2026-08-11 工作记录

## 排查：Docker 部署后 /oes/assets/*.js 返回 text/html（应为 application/javascript）

### 现象
本地（直接访问引擎 :9999）`http://localhost:9999/oes/assets/index-<hash>.js` 返回 application/javascript；
服务器上经外层反代访问同一路径返回 text/html。

### 根因
1. 外层反代 `deploy/nginx.conf` / `docker/external-nginx.example.conf` 路由规则：
   - /oes/collab、/oes/embed、/oes/api/{token,health,convert} → 引擎容器 :9999
   - 通用 `location /oes/ { proxy_pass http://umo_demo; }` → demo 容器 :9998
   但 /oes/assets/ 没有显式指向引擎的 location 规则，落入通用规则被转发到 demo 容器。
2. demo 容器 nginx 有 `try_files $uri $uri/ /oes/index.html` 的 SPA 兜底；
   demo 镜像里根本没有引擎的带 hash 的编辑器 bundle，于是回退返回 demo 的 index.html（text/html）。
3. 深层冲突：引擎 iframe 与 demo SPA 都把自己的前端构建产物放在 /oes/ 前缀下，
   二者都用 /oes/assets/<hash>.js，URL 命名空间重叠。在单一域名/端口的反代后面，
   这两套前端资源无法同时正确解析。
   本地之所以正常：demo 的 iframe 通过 UMO_ENGINE_PUBLIC_URL(默认 http://localhost:9999/oes)
   直接指向引擎自身端口，引擎资源从不经过 demo 路径。

### 修复方向（取决于部署拓扑）
- 推荐（改动最小、与本地一致）：让 iframe 直接加载引擎自身可达地址。
  设 UMO_ENGINE_PUBLIC_URL=http://<服务器IP或域名>:9999/oes，并确保引擎容器 9999 端口对外可达；
  外层反代只服务 demo。无需改 nginx。
- 若必须单域名单端口（不暴露 9999）：需给引擎 embed 单独前缀（如 /editor/），
  改 embed vite base + 引擎 nginx + demo UMO_ENGINE_PUBLIC_URL —— 较大改动。
- 不要简单加 `location /oes/assets/ { proxy_pass http://umo_engine; }`：会让 demo 页面自身的
  /oes/assets/ 被路由到引擎而 404→引擎 index.html（text/html），即修好 iframe 但弄坏 demo 页面。

## 实施：引擎改用 /oes/embed/ 前缀（单域名方案）

用户选定「单域名 + 引擎独立前缀 /oes/embed/」。已落地修改：

1. `embed/vite.config.js`：base `/oes/` → `/oes/embed/`（引擎静态资源与 demo 的 /oes/assets/ 错开）
2. `docker/Dockerfile`：embed dist COPY 目标 `/app/public/oes` → `/app/public/oes/embed`
3. `docker/nginx.conf`（引擎容器内）：
   - `location = /oes/embed` rewrite 目标 → `/oes/embed/index.html`
   - 静态资源 location `location /oes/` → `location /oes/embed/`（try_files 兜底 /oes/embed/index.html）
   - API/WS（/oes/api/*、/oes/collab）保持不变
4. `deploy/nginx.conf` 与 `docker/external-nginx.example.conf`（外层反代）：
   - 新增 `location = /oes/embed` + `location /oes/embed/` → 引擎容器 :9999
   - 删除误导注释（原注释声称 /oes/assets/ 归引擎但无实际规则）
   - 通用 `location /oes/` → demo 容器不变；最长前缀匹配自动分流
5. `docker/docker-compose.yml` / README / build 脚本：注释与文档同步

关键设计点（已验证链路）：
- demo `getEmbedUrl` = `${engineUrl}/embed`，故 `UMO_ENGINE_PUBLIC_URL` 仍配 `/oes`（**不要带** /embed）
- embed `base-path.js` 从 URL 结尾 `/embed` 推导前缀 `/oes` → WS `/oes/collab`、convert `/oes/api/convert` 不受影响
- 引擎 index.html 引用 `/oes/embed/assets/*.js` → 外层 nginx `/oes/embed/` → 引擎 → application/javascript
- demo 自身 `/oes/assets/*.js` → 外层 `/oes/` → demo，两者不再互相兜底

⚠️ 部署提醒：需**重新构建引擎镜像**（tar 包里的旧镜像还是 /oes/ 前缀），demo 镜像不用重建（UMO_ENGINE_PUBLIC_URL 是运行时 env）。

## 排查：/oes/api/doc-token 返回 500

### 现象
外层 nginx(8080) 已配好 /oes/embed/ 规则，`http://localhost:8080/oes/documents/<id>` 页面正常；
`http://localhost:8080/oes/api/doc-token` 返回 500。

### 根因（用户把 UMO_ENGINE_URL 配成 http://localhost:8080/oes/embed，三个错误叠加）
1. **localhost 在容器内指向 demo 容器自己**：UMO_ENGINE_URL 是 demo-server(容器内) → 引擎 的
   服务间调用地址。demo 容器里 localhost:8080 无监听 → fetch 抛 ECONNREFUSED →
   demo-server 全局 catch（index.js 243-246 行）→ 500。
2. **路径带 /embed 错误**：demo-server 拼 `${UMO_ENGINE_URL}/api/token`，UMO_ENGINE_URL 必须是
   引擎根地址（带 /oes 即可）。即便网络通，/oes/embed/api/token 也会被外层 nginx 的
   /oes/embed/ 透传到引擎，引擎静态 location 兜底返回 index.html，拿不到 JWT。
3. **服务间调用不该绕宿主 nginx**：compose 网络内用服务名 http://umo-editor-engine:9999/oes 最稳。

### 修复
docker-compose.yml：UMO_ENGINE_URL 改回 `http://umo-editor-engine:9999/oes`（已改，并加注释警告）。
生效需重建 demo 容器：docker compose up -d umo-editor-demo。
⚠️ 若引擎设了 UMO_API_KEY，demo 的 UMO_API_KEY 必须一致，否则 doc-token 变 401（不是 500）。
⚠️ 单入口部署时 UMO_ENGINE_PUBLIC_URL（浏览器 iframe 用）可配 http://localhost:8080/oes 走外层 nginx；
   UMO_ENGINE_URL（服务间）绝不能用浏览器地址概念配置。

## 排查：导出回传 /oes/api/receive-doc 报 500（已修复）

### 根因（demo-server 代码 bug）
`demo/server/index.js` 用了 `extname(original)`（saveMultipartFile 里给上传文件取扩展名），
但顶部 import 只有 `{ dirname, join } from 'path'`，**缺 extname**。
回传文件时 busboy 'file' 事件回调抛 ReferenceError: extname is not defined →
异常不在路由 try/catch 内 → demo-server 进程崩溃 → supervisor 重启 →
nginx 反代 4001 失败返回 50x（本地直连 demo nginx 是 502，外层 nginx 场景显示 500）。
本地之前「正常」是因为没触发过文件上传路径（JSON API 和页面不受影响）。

### 顺带修复的次生 bug
receive-doc 成功时返回 `fileUrl = url.origin + '/api/files/...'`，url.origin 基于 Host header，
经 nginx 透传后是 `$host`（无端口）+ 缺 /oes 前缀 → 下载链接打不开。
改为返回相对路径 `/oes/api/files/<name>`（带 /oes 前缀），浏览器自动继承页面域名端口。

### 修复
1. `demo/server/index.js:21` → `import { dirname, join, extname } from 'path'`
2. `demo/server/index.js` receive-doc → `const fileUrl = \`/oes/api/files/${encodeURIComponent(saved.filename)}\``
3. 本地已重建 demo 镜像验证：上传 200、下载 200、日志无 ReferenceError。
⚠️ 服务器需重新构建/导入 demo 镜像（docker compose up -d --build umo-editor-demo）。
检查过 comments.js 无同类未 import 问题。
